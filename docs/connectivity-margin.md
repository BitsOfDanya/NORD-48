# Dynamic min-cut / Resilience Margin

Метрика показывает минимальное число **отказов спутников**, после которых
выбранный клиент потеряет связь со всеми шлюзами в динамическом графе
контактов.

- В cut могут входить только вершины с `kind="satellite"`.
- Клиент и шлюзы не являются кандидатами на удаление.
- Для нескольких шлюзов связь считается потерянной, только когда клиент
  отрезан от каждого из них.
- Если маршрута уже нет, возвращаются `vertex_connectivity: 0` и
  `critical_satellites: []`.
- `critical_satellites` — **один детерминированно выбранный минимальный
  cut**, а не объединение спутников из всех возможных минимальных cut.

В запросе нужно передать ровно один источник: `scenario_id`, полный
`scenario` или существующий `run_id`. Время `t_s` измеряется в секундах
от начала сценария; старое имя `timestamp` также принимается как alias.

## Расчёт одного timestamp

`POST /api/v1/resilience/connectivity-margin`

```json
{
  "scenario_id": "01_full_constellation",
  "client_id": "C70",
  "t_s": 21600
}
```

Реальный ответ для штатного сценария:

```json
{
  "client_id": "C70",
  "t_s": 21600.0,
  "vertex_connectivity": 2,
  "critical_satellites": ["S09", "S39"]
}
```

Это означает, что в данном snapshot отказ любого одного спутника ещё не
разрывает связь, а указанный минимальный набор из двух спутников разрывает
связь клиента со всеми шлюзами.

## Агрегация по суткам

`POST /api/v1/resilience/connectivity-margin/daily`

```json
{
  "scenario_id": "01_full_constellation",
  "client_id": "C70"
}
```

Сокращённый реальный ответ для 720 шагов с интервалом 120 секунд:

```json
{
  "client_id": "C70",
  "step_s": 120,
  "days": [
    {
      "day_start_s": 0,
      "day_end_s": 86400,
      "samples_evaluated": 720,
      "minimum_vertex_connectivity": 0,
      "mean_vertex_connectivity": 1.2944444444444445,
      "average_when_connected": 1.310829817158931,
      "no_route_pct": 1.25,
      "margin_1_pct": 68.19444444444444,
      "margin_2_pct": 30.416666666666668,
      "margin_3_plus_pct": 0.1388888888888889,
      "critical_satellites": [
        {
          "satellite_id": "S29",
          "critical_samples": 24,
          "critical_fraction": 0.03333333333333333
        },
        {
          "satellite_id": "S17",
          "critical_samples": 22,
          "critical_fraction": 0.030555555555555555
        }
      ]
    }
  ]
}
```

В примере список частот сокращён до двух записей. Проценты
`no_route_pct`, `margin_1_pct`, `margin_2_pct` и `margin_3_plus_pct`
образуют полное распределение и в сумме дают 100%. Поле
`average_when_connected` усредняет только значения больше нуля и равно
`null`, если за весь интервал связи не было.

Частота относится к одному minimum cut, выбранному на каждом шаге. При
наличии нескольких равнозначных cut она не означает частоту участия
спутника во всех возможных cut.

## Производительность

Контрольное измерение выполнено через FastAPI `TestClient` в Docker на
сценарии `01_full_constellation`, клиент `C70`:

- один timestamp: в среднем 6,0 мс (20 прогонов, 4,5–7,8 мс);
- сутки, 720 шагов: 2,40 с.

Daily endpoint синхронный. При текущем размере сценария отдельный async-job
не требуется; время растёт вместе с числом временных шагов и размером
графа.
