# Порог отказоустойчивости

## Exact N-2

`POST /api/v1/resilience/failure-threshold/n2` проверяет каждую неупорядоченную
пару активных аппаратов. Для 48 аппаратов это ровно `C(48,2) = 1128` вариантов,
без sampling и дублей. Оба аппарата недоступны на всём выбранном интервале;
scenario и baseline-графы остаются неизменными.

Reference geometry и 720 contact graphs строятся один раз. Для каждой пары
проверяется существование допустимого пути `client → satellites → gateway`, с
запретом транзита через чужого клиента. Это точный критерий availability и
outage для всех поддержанных routing strategies: стратегии выбирают разные
пути, но при одном графе одинаково отвечают на вопрос о существовании пути.

Для пары возвращаются worst-client availability, падение относительно
baseline, нарушения target, рост max outage, failure-induced outage steps,
затронутые клиенты и top-10 N-1 membership. Ранжирование: больше нарушений
target, ниже worst availability, больше max outage, затем ID.

«Дополнительный эффект пары» считается для worst-клиента пары:

`pair drop − (single A drop + single B drop)`.

Положительное значение означает, что совместное удаление создаёт потерю сверх
суммы двух одиночных эффектов. Формула использует одного и того же клиента во
всех трёх слагаемых.

## Фактический результат

Для `01_full_constellation`, полного горизонта и `minimum_hops` проверены все
1128 пар за 8,76 с. Ни одна не опустила клиента ниже 90%, поэтому найденный
порог обозначается `> 2`; exhaustive N-3 автоматически не запускается.

Худшая пара — `S19 + S29`: C65 меняется `96,67% → 91,53%`, падение
5,14 п.п., рост max outage 240 с, дополнительный эффект +0,56 п.п. Среди 40
концов top-20 пар 30 принадлежат top-10 N-1: связь существенная, но не полная.

Вкладка «Порог отказоустойчивости» показывает N-1/N-2 counts, худшую пару,
top-20 и кнопку подсветки двух аппаратов на глобусе. Подсветка не запускает
failure experiment.
