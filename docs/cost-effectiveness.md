# Cost / Economics Layer

Отвечает на вопрос «сколько это стоит» настолько честно, насколько
позволяют реально доступные данные — то есть **почти никак**, если
пользователь не задал цену сам. См. docs/cost-sources.md — почему ни один
проверенный публичный источник не даёт применимую «цену за спутник в ценах
2026 года» без дополнительных допущений.

## Два режима, оба всегда доступны

### Resource-only (по умолчанию)

Только количество: сколько активных спутников, сколько партий запуска
использовано, сколько пусков потребуется при заданной вместимости пуска.
Ни одного рубля. Это единственные числа, которые не являются догадкой —
они следуют напрямую из выбранной конфигурации (`resource_summary()`,
`backend/app/calculation/economics/cost_model.py`).

### Cost mode (opt-in)

Активируется, только если пользователь ЯВНО указал
`satellite_unit_cost_rub` — иначе `estimate_cost()` возвращает `None`, а
не подставляет какое-либо число «по умолчанию». Каждое производное число —
простая, проверяемая арифметика ровно из введённых пользователем полей:

```
satellite_cost   = satellite_count × satellite_unit_cost_rub
estimated_launches = ceil(satellite_count / launch_capacity_satellites)   [если задана вместимость]
launch_cost      = estimated_launches × launch_fixed_cost_rub
subtotal         = satellite_cost + launch_cost + integration_cost_rub
total            = subtotal × (1 + reserve_percent / 100)
```

Никакой инфляции, никакого пересчёта в «цены 2026 года», никакого
«рыночного коэффициента» — только то, что ввёл пользователь. Историческая
оценка (Sitronics, дек. 2021 — см. docs/cost-sources.md) доступна во
фронтенде как отдельная кнопка-пресет, заполняющая поля явно видимыми
значениями с пометкой источника и датой — никогда не применяется тихо.

## Cost-effectiveness метрики

- `cost_per_availability_point(cost, worst_availability_percent)` — полная
  стоимость, делённая на достигнутый процент доступности худшего клиента.
  Простое отношение эффективности, не свёрнутый в один «рейтинг» индекс.
  `None`, если доступность ⩽ 0 (деление было бы бессмысленным).
- `incremental_cost_per_pp(cost_before, avail_before, cost_after,
  avail_after)` — цена ОДНОГО дополнительного процентного пункта
  доступности при переходе от одного кандидата к другому (например, N=44
  → N=45). `None`, если доступность не выросла — прирост, идущий вниз, не
  является «ценой», это была бы бессмысленная отрицательная величина.
- `estimated_cost_delta(cost_a, cost_b)` — знаковая разница полной
  стоимости между двумя кандидатами.

## Pareto-представление (спутники/стоимость vs доступность)

На вкладке «Ресурсы и экономика» (`frontend/.../economics-panel.tsx`)
пользователь может оценить любой кандидат (например, каждую точку из
таблицы порога Threshold Verification или каждый Stage деплой-планировщика)
и сравнить итоговую стоимость с достигнутой доступностью — так виден
компромисс "больше спутников → выше доступность → выше стоимость" без
скрытой свёртки в один "оптимальный" ответ.

## API

`POST /api/v1/economics/estimate` — принимает `EstimateRequest`
(количество спутников, партий, опционально допущения о ценах),
возвращает `mode: "resource_only" | "cost"`, `resources`, `cost` (`null`
в resource-only режиме) и `cost_per_availability_point_rub` (только если
передан `worst_availability_percent`). См. `backend/app/api/v1/economics.py`
и `backend/tests/integration/test_economics_api.py`.

## Ограничения

- Нет ни одного зашитого в код значения цены — все примеры в UI явно
  помечены как «историческая оценка», «ориентировочно», «не коммерческое
  предложение».
- `estimated_launches` — просто `ceil(count / capacity)`, не учитывает
  реальные ограничения конкретной ракеты-носителя (совместимость по массе,
  диаметру обтекателя, орбитальному наклонению) — это чисто арифметическая
  верхняя оценка количества пусков, не инженерный расчёт пусковой схемы.
- Стоимость интеграции/резерва — поля, которые пользователь задаёт сам;
  система не предлагает для них никакого значения по умолчанию, кроме 0.
