# Робастная оптимизация для отказа 10 аппаратов

Режим `mode="failure_cvar"` решает отдельную задачу: сохранить штатный
`target_availability`, а среди штатно допустимых конфигураций максимизировать
нижний CVaR доступности при отказе ровно десяти спутников.

## Банк отказов

Начальный банк состоит из трёх классов:

1. фиксированный набор из `03_satellite_outages`;
2. воспроизводимые равномерно-случайные наборы без повторов;
3. коррелированные наборы соседних орбитальных слотов одной плоскости.

Фиксированный профиль также задаёт интервал отказа. Для исходного кейса это
`[21600, 86400)`. Failure availability и максимальный перерыв считаются только
на этом пост-отказном интервале: первые шесть штатных часов больше не маскируют
деградацию. Штатное ограничение отдельно проверяется на полном горизонте.

Нижний `CVaR(alpha)` — средняя доступность в худшей доле `alpha` банка.
Реализация учитывает дробную массу границы хвоста, поэтому определение не
зависит скачком от округления `alpha × bank_size`.

## Adversarial generation

После каждого outer-поиска RAAN/phase запускается внутренний tabu-guided
поиск тяжёлого нового набора из десяти аппаратов. Он стартует из худшего
известного набора, исследует one-swap соседей, не дублирует уже известные
комбинации и добавляет лучший новый набор в банк. Затем RAAN/phase заново
оптимизируются уже против расширенного банка.

`budget` задаётся на один outer-раунд. Поэтому полный заявленный progress равен
`budget × (adversarial_rounds + 1)`. `adversarial_search_budget` — отдельное
число failure-set кандидатов на внутренний раунд.

## Производительность и точность

Для каждого кандидата RAAN/phase орбитальная геометрия и контактные графы
строятся один раз. Разные наборы отказов применяются к ним точным удалением
узлов на заданном интервале. Это не surrogate и не приближение физики; повторно
используется только неизменная геометрия.

Ранжирование двухуровневое:

1. любой кандидат, выполняющий штатный target для всех клиентов, лучше любого
   невыполняющего;
2. среди допустимых максимизируется CVaR, затем worst failure-set availability,
   уменьшается худший перерыв и только потом учитываются штатный запас и
   отклонение углов от baseline.

Результат содержит `failure_bank`, `optimization_rounds`, пост-отказное окно и
блок `failure_robust` у каждого кандидата. Режим доступен в UI на вкладке
«Поиск RAAN/phase».
