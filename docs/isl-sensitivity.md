# ISL Range Sensitivity

Отвечает на инженерный вопрос «какая минимальная дальность
межспутниковой линии (ISL) нужна этой конфигурации, чтобы достичь
target?» — обратная задача по отношению к обычной симуляции (там
`isl_range_km` — вход, доступность — выход; здесь ищется минимальный вход,
дающий нужный выход).

## Метод: точный sweep, не аппроксимация

`backend/app/calculation/optimization/isl_sensitivity.py`:

1. **Coarse sweep** (`isl_sweep`) — на каждой заданной точке сетки
   `isl_range_km` выполняется ПОЛНЫЙ точный пересчёт (720 шагов, тот же
   pipeline, что и обычная симуляция) — никакой интерполяции между
   точками, только реально посчитанные значения.
2. **Refine** (`refine_isl_boundary`, опционально) — если известна
   ближайшая непроходящая и ближайшая проходящая точка грубой сетки, между
   ними строится более мелкая сетка (по умолчанию шаг 50 км) — тоже точные
   пересчёты, просто на более узком интервале.
3. **Минимум** (`minimum_isl_for_target`) — первая по возрастанию точка
   (среди грубой + уточнённой сетки), где `worst_availability` всех
   клиентов достигает target.

## Допущение о монотонности

Функция минимума опирается на физическое допущение: **увеличение
допустимой дальности ISL никогда не уменьшает достижимую связность** —
более длинная линия добавляет возможные контакты, никогда не убирает уже
существующие. Отсюда: первая проходящая точка по возрастанию — минимум
СРЕДИ ПРОВЕРЕННЫХ значений, а не гарантированный глобальный минимум (если
сетка слишком грубая, между двумя протестированными точками может
существовать более мелкая проходящая точка, которую sweep не увидел, —
для этого и нужен `refine`).

## Пример: `01_full_constellation`

Grid `[1000, 1250, 1500, 1750, 2000, 2250, 2500, 3000]` км + refine 50 км →
минимальная дальность ISL для target ≥90%: **2750 км** (получено через
API `/api/v1/optimization/isl-sensitivity`, см. скриншот в отчёте сессии).
Ниже этой границы worst availability монотонно растёт от ~5% (1000 км) до
~86% (2650 км) и выходит на плато ~96-99% после ~2750 км.

## API

`POST /api/v1/optimization/isl-sensitivity` — `IslSensitivityRequest`
(`scenario_id`/`scenario`, `routing_strategy`, `isl_values_km`, `refine`,
`refine_step_km`) → `IslSensitivityResult` (`coarse_points`,
`refined_points`, `minimum_isl_range_km`, `minimum_isl_found`). Синхронный
эндпоинт (не async job) — объём вычислений ограничен размером
пользовательской сетки, не растёт со сложностью поиска.

## Ограничения

- Стоимость линейна по числу точек сетки — каждая точка это полная
  720-шаговая симуляция; слишком мелкая сетка на широком диапазоне
  дорога. Разумная практика — грубая сетка с шагом ~250 км + refine на
  найденной границе.
- Не учитывает физическую реализуемость самой дальности (мощность
  передатчика, диаграмма направленности, доплеровский сдвиг) — это чисто
  геометрический/связностный расчёт поверх уже заданной модели контакта.
- Результат специфичен для ОДНОЙ конкретной конфигурации (RAAN/phase/
  состав спутников) — смена конфигурации требует нового sweep.
