# Демо-сценарий (3–5 минут)

Короткий, воспроизводимый порядок показа — не история сессий, а
последовательность действий для защиты. Все цифры ниже — уже
верифицированные числа (см. `docs/design-decision.md`,
`docs/robust-design-search.md`), не иллюстрации.

## 1. Опорный сценарий (~30с)

`/` → загрузить `01_full_constellation`, запустить расчёт. Показать
глобус, временную шкалу, маршрут клиента C65 в 2-3 разных моментах.

## 2. Проблема baseline (~20с)

`/summary` → худшая доступность 96.67% (Normal), но под `03_satellite_outages`
79.31% и под `04_link_range` (ISL 2000 км) 62.22% — деградация значительна.

## 3. Рекомендация Robust Design 2.0 (~30с)

`/optimizer` → режим `robust_design` → показать найденную конфигурацию:
Normal 96.53%, Outages 82.64%, ISL2000 67.78%, N-1 PASS, N-2 PASS,
backup mean 30.05%. Прочитать вслух `_recommendation()` — она уже называет
конкретного клиента и trade-off, не общие слова.

## 4. Сравнение (~20с)

`/compare` → baseline vs Robust 2.0, deltas по каждому клиенту (включая
честно показанный регресс C65 под ISL2000, если он есть в выбранной паре).

## 5. Отказы: N-1/N-2 (~30с)

`/resilience` → «Критичность · N-1»: худший спутник, снижение доступности.
«Порог · N-2»: 1128 пар, 0 нарушающих target. Оба PASS для Robust 2.0.

## 6. Connectivity Margin (~30с)

`/resilience` → «Резерв маршрута» → dynamic min-cut для одного клиента в
момент времени + суточная агрегация (margin 0/1/2/3+ %). Объяснить: не то
же самое, что N-1/N-2 (см. `docs/connectivity-margin.md`).

## 7. Почему именно так плохо: Bottleneck Decomposition (~30с)

`/` → снять метрики клиента под ISL2000 → показать `bottleneck_breakdown`:
у C70 36.53% горизонта — именно `ISL_NETWORK_SPLIT`, не потеря видимости.
Это объясняет ЧИСЛО, а не просто показывает его.

## 8. Deployment: с чего начать разворачивание (~40с)

`/optimizer` → Deployment Planner, включить «планировать под геометрию
Recommended Robust». Показать: наивный Stage 1 (все 16 спутников одной
плоскости) даёт 13.19% worst availability; жадно подобранный состав
(5/6/5 по плоскостям) даёт **32.22%** — тот же бюджет запуска, кардинально
устойчивее. То же для Stage 2 (32 спутника): 56.53% → 65.56%.

## 9. Resilience Passport (~20с)

`/summary` → единая карточка: Normal/N-1/N-2/backup/connectivity/ISL/CVaR
и честный вердикт одной строкой — не дамп метрик по отдельным страницам.

## 10. Export (~20с)

`/` → «Экспорт» → показать `schema_version: cosmo-A-result-1.0`,
`effective_scenario`, `routes`. Показать, что тот же файл можно снова
загрузить как сценарий (export → re-upload → повторный расчёт).

## Что говорить, если спросят «а глобальный оптимум?»

Честно: поиск (toroidal DE + multi-start + local pattern search) —
эвристика, не доказательство глобального оптимума; см.
`docs/robust-design-search.md` → «Robust 3.0 research attempt» — там
задокументирован реальный отрицательный результат попытки улучшить
Robust 2.0 дальше (кандидат провалил exact N-1/N-2).
