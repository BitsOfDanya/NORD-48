# Соответствие требованиям кейса

Кейс: **«Проектирование устойчивой спутниковой группировки»**
(КосмоХакатон 2026). Полный текст — в `case_materials/`:
«Постановка задачи», «Описание данных», «Критерии оценки». Ниже —
сопоставление функциональных требований постановки задачи с фактической
реализацией NORD-48 v0.1.

## 1. Подготовка и изменение конфигурации

| Требование | Реализация | Статус |
| --- | --- | --- |
| Загрузка сценария из предоставленного набора | `GET /scenarios/examples`, `GET /scenarios/examples/{id}` | готово |
| Отображение состава группировки, плоскостей, наземных пунктов, параметров расчёта | панель «Конфигурация» во frontend | готово |
| Загрузка собственного сценария того же формата | `POST /scenarios/upload` + кнопка «Загрузить JSON» | готово |
| Выбор очереди запуска (launch_stage) в интерфейсе | редактируется в копии выбранного сценария | готово |
| Изменение RAAN и фазирования плоскостей | редактируется по каждой плоскости без изменения исходного файла | готово |
| Добавление периодов недоступности спутников через интерфейс | форма выбора спутника и интервала в секундах | готово |
| Сохранение варианта и возврат к нему для сравнения | варианты и история запусков сохраняются в памяти текущей сессии; постоянная БД не подключена | частично |

## 2. Моделирование покрытия и сети

| Требование | Реализация | Статус |
| --- | --- | --- |
| Положения активных спутников на каждом шаге | `geometry.py` организаторов через адаптер, `GET /simulations/{run_id}/snapshot` | готово |
| Видимость наземных пунктов | учитывается в `snapshot.edges` и в диагностике (`NO_VISIBLE_SATELLITE`) | готово |
| Доступные межспутниковые связи | `snapshot.edges` (тип `isl`), отображаются на глобусе | готово |
| Просмотр состояния сети в выбранный момент времени | временная шкала + `snapshot?t_s=` | готово |
| Периоды отсутствия связи по пункту | `GET /simulations/{run_id}/timeline`, полоса доступности под шкалой | готово |

## 3. Маршрутизация и реакция на отказы

| Требование | Реализация | Статус |
| --- | --- | --- |
| Маршрут от наземного пункта до шлюза через спутниковую сеть | `GET /simulations/{run_id}/route` | готово |
| Пересчёт маршрута при изменении положения/доступности аппаратов | маршрут вычисляется заново на каждый шаг симуляции | готово |
| Причина отсутствия маршрута (нет видимого спутника / разрыв сети / нет контакта со шлюзом / его недоступность) | 4 категории диагностики — `NO_VISIBLE_SATELLITE`, `ISL_NETWORK_SPLIT`, `NO_GATEWAY_CONTACT`, `GATEWAY_OUTAGE` | готово |
| Свободный выбор способа поиска маршрута (команда сама решает) | реализованы 2 стратегии — минимум переходов (BFS) и минимальная длина (Дейкстра) | готово |

## 4. Сравнение вариантов и рекомендации

| Требование | Реализация | Статус |
| --- | --- | --- |
| Сопоставление минимум двух сохранённых вариантов | режим «Сравнение» + `POST /comparisons` | готово |
| Сравнение по доступности, перерывам, характеристикам маршрутов | изменённые параметры, метрики и дельты от первого запуска | готово |
| Расчёт для полной группировки, промежуточного этапа и сценария отказов | все 4 исходных сценария (включая нужные три) считаются полностью и проходят регрессионные тесты | готово |
| *(доп.)* Автоматический подбор конфигурации | Differential Evolution по RAAN/phase; каждый кандидат проверяется точным движком | готово |
| *(доп.)* Поиск наиболее уязвимых аппаратов | полный N-1 по активным аппаратам | готово |
| *(доп.)* Анализ резервных путей | lifetime маршрута, запас слабейшей линии и N-1 критичность реализованы; число независимых путей и минимальные разрезы пока не считаются | частично |
| *(доп.)* Сравнение стратегий маршрутизации | стратегия выбирается перед запуском расчёта; сравнение результатов двух стратегий бок о бок не реализовано | частично |

## Требования к интерфейсу

| Требование | Реализация | Статус |
| --- | --- | --- |
| Схема/карта со спутниками, наземными пунктами, связями и выбранным маршрутом, с подписями | 3D-глобус (react-globe.gl): активные/недоступные спутники, пункты, шлюз, ISL, выделенный маршрут, подписи по наведению | готово |
| Временная шкала и диаграмма доступности по каждому пункту | шкала с воспроизведением + цветная полоса доступности выбранного клиента | готово |
| Сравнение вариантов: изменённые параметры, итоговые показатели, различия | отдельный режим «Сравнение» | готово |
| Понятное сообщение об ошибке при загрузке некорректного файла | понятный текст + раскрываемые технические подробности | готово |
| Сброс изменений и повторный запуск | возврат к исходному сценарию очищает редактируемую копию; новый запуск доступен в шапке | готово |

## Базовые сценарии проверки (из постановки задачи)

| Сценарий проверки | Статус |
| --- | --- |
| Полная группировка: загрузка `01_full_constellation.json`, расчёт, выбор пункта, маршрут в разные моменты времени | готово |
| Этап развёртывания: переключение очереди запуска и сравнение доступности | готово — этап меняется в редактируемой копии, результаты попадают в историю сравнения |
| Отказ аппарата: выбрать спутник на маршруте, задать недоступность, пересчитать | готово — форма добавляет отказ выбранного спутника на заданный интервал |
| Изменение проекта: RAAN/фазирование одной плоскости, сохранение, сравнение, экспорт/повторная загрузка | готово в рамках сессии; постоянное хранение вариантов требует БД |

## Данные и расчётный модуль

Все 4 сценария из комплекта используются без изменений
(`data/scenarios/raw/`), `geometry.py` организаторов используется как
есть, без переписывания (`case_materials/calculation/geometry.py` →
`backend/app/calculation/geometry/reference_geometry.py`). Формат
выгрузки результата — `GET /simulations/{run_id}/export` (см.
[api.md](api.md)).
